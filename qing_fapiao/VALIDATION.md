## 七项独立事务验证

贸易仓库脚本：`scripts/qa/fapiao_provider_concurrency.py`。
脚本只允许 `qing_cnf_*` 一次性测试数据库，使用独立 cursor、事务提交、两个线程与
Repeatable Read 快照屏障；遇到序列化冲突后以新事务重试。
脚本会写入并提交合成测试数据，不能在客户业务库运行。

| 场景 | 已验证结果 |
| --- | --- |
| 两个 worker 处理同一任务 | 仅一次 submit，最终只完成一次登记 |
| 服务商受理后超时 | 保留未知状态和财务预占，后续只 query 原请求 |
| 受理后本地响应丢失 | 预先提交的发送标记仍存在，恢复时不再次 submit |
| 并发重复回调 | 同一事件返回同一记录，仅完成一次登记 |
| 登记失败后并发重试 | 保留已开票状态，重试仅执行本地登记并返回同一税票 |
| 取消与首次发送竞争 | 不会同时取消申请释放额度并提交开票 |
| 首次任务创建与账号身份修改竞争 | 两者不能同时成功破坏账号身份冻结 |

执行结果为七项 `PROVIDER_QA ... OK`，最终输出 `PROVIDER_QA ALL_OK`。
进程丢失场景通过提交发送标记、调用合成适配器后回滚本地响应模拟；
它验证数据库事务边界，不代表经过真实服务商或操作系统强制终止的故障演练。

衔接测试中的 `test_50_and_150_line_edit_and_queue_scaling` 在 savepoint 内测量并回滚，
分别验证单行编辑及全单创建接口任务的查询增长。

序列化工作量与数据大小随行数增加。SQL 数量是此测试环境结果，不作为所有扩展模块组合的性能保证。

## 安全与交付范围

- 公共模块不开放匿名通用回调路由。未来服务商控制器必须先对原始报文验签，再交给私有通知入口。
- 发送前以独立事务持久化未知状态，处理期间使用跨提交的任务锁；超时或响应格式错误不会恢复成可重新发送状态。
- 外部已开票与本地已登记分开保存。未确认、处理中或已开票任务不能通过取消申请释放预占额度。
- `qing_fapiao_mock` 仅允许测试模式，返回带 `MOCK-` 编号和明显合成标识的 XML，不调用网络。
- Qing 衔接默认禁止测试票进入台账；测试参数仅在隔离测试库中显式启用。RPC context 不能绕过该限制。
- 本轮未接入真实服务商、未执行真实开票、红字申请或作废。协议预留多票结果，Qing 首版只自动登记单票。

中文浏览器验收和部署状态由主任务另行记录；本文不以服务器测试替代客户实际数据验收。

最终状态字段依赖与界面描述调整后，模拟器 5 项和 Qing 衔接 15 项定向重测通过（20 项，0 失败／0 错误）。包含申请页缓存的登记状态从待登记 → 登记异常 → 已登记更新验证；没有重新运行无关测试来重复计数。

中文浏览器合成流程已验证：申请提交／审核、选择模拟服务商、创建任务；独立 worker 执行后刷新页面可见任务已开票／已登记，申请已回填并关联税票。数据库独立读回确认一次发送、分配已确认及预占归零。尚未实现状态推送，后台执行后须刷新页面。未部署生产。
